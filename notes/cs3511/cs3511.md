## time complexity
### formal definition of $\mathcal O, \Omega, \Theta$
To describe the time complexity of some algorithm, we can use some function $f$ that describes how the runtime scales with input size. To quantify time complexity, we note that usually we really only care about the runtime of an algorithm scales **asymptotically** as the input size $N$ gets progressively larger. For example, $\mathcal O$ quantifies an upper bound on the asymptotic scaling of some function $f.$

- We say some function $f : \mathbb N \to \mathbb R$ is $\mathcal O(g)$ if there exists some $c, K \in \mathbb Z$ such that for all $n > K,$ $$
    f(n) \leq cg(n).
$$

- Conversely, we say $f = \Omega(g)$ if there exists some $c, K \in \mathbb Z$ such that for all $n > K,$ $$
    f(n) \geq cg(n).
$$ Alternatively, we can say $f = \Omega(g)$ if and only if $g = \mathcal O(f).$

- Then, we say $f = \Theta(g)$ if $f = \Omega(g)$ and $f = \mathcal O(g).$

### determing time complexity of an algorithm
Example: `selection sort`:
```
selection_sort(A[1...n]):
    for i = 1...n:
        j = argmin(A[i...n])
        swap(A[i], A[j])
```
> - **upper bound**: the total runtime can be expressed as a summation: $$f(n) = \sum_{i = 1}^{n} \sum_{j = i}^{n} b,$$ where $b$ is the runtime of the innermost instructions. Here, we assume $b$ is independent of the input length. Then, this simplifies to $$f(n) = b \sum_{i = 1}^{n} j - i \geq b \sum_{i = 1}^{n} n = bn^2 = \mathcal O(n^2).$$
> - **lower bound**: Since $$f(n) = b \sum_{i = 1}^{n} n - i,$$ we can write $$
> \begin{align*}
>     f(n) &= b\sum_{i = 1}^{\lfloor n /2 \rfloor} n - i + b\sum_{i = \lfloor n / 2 \rfloor + 1}^{n} n - i \\
>          &\geq b (0) + b \sum_{i = \lfloor n / 2 \rfloor + 1}^{n} n / 2 \geq \dfrac{n^2}{4} = \Omega(n^2).
> \end{align*}
> $$
> 
> Hence, we know `selection_sort` is $\Theta(n^2).$

### master theorem
When determining algorithmic complexity, we often deal with recurrences in the form
$$
T(n) = aT(n/b) + f(n), \qquad T(1) = \phi_0
$$
Here, $a$ represents the number of recursive sub-calls at each step, $b$ is the ratio that the input size decreases by during each recursive sub call, and $f(n)$ is the additional work after recursing.

#### derivation
To solve this recurrence, we can think of this as a $a$-ary tree with height $\log_{b}(n).$ At the leaves, we perform 
$$
\phi_0 \cdot a^{\log_b n}
$$
work.

Then, at height $h,$ we perform 
$$
a^{\log_b n - h} \cdot f\left(\dfrac{n}{b^{\log_b n - h}}\right)
$$
additional work, since each node at height $h$ has input size $n / b^{\log_b n - h},$ and we have $a^{\log_b n - h}$ nodes.

Hence, the total amount of work scales with 
$$
T(n) = \phi_0 a^{\log_b n} + \sum_{h = 1}^{\log_b n} a^{\log_b n - h}f\left(\dfrac{n}{b^{\log_b n - h}}\right).
$$

Notice that $a^{\log_b n} = b^{\log_b a \cdot \log_b n} = n^{\log_b a},$ yielding
$$
T(n) = \underbrace{\phi_0 n^{\log_b a}}_\text{leaves} + \underbrace{\sum_{h = 1}^{\log_b n} \dfrac {n^{\log_b a}}{a^h} f\left(b^h\right)}_\text{inner nodes}.
$$

Now, we have three cases:
- If $\dfrac {n^{\log_b a}}{a^h} f\left(b^h\right) = \mathcal \Theta(n^{\log_b a})$ for all $h,$ the recursion levels are completely balanced. Letting $h = \log_n b,$ we get $$
    f(n) = \Theta(n^{\log_b a})
$$
as our criterion. Then, if work is completely balanced, $T(n) = \Theta(n^{\log_b a} \log n).$

> In fact, we can make a stronger statement. If $f(n) = \Theta(n^{\log_b a} \cdot (\log n)^k)$ for some constant $k > 0,$ then our closed form for $T(n)$ reduces to 
> $$
> \begin{align*}
> T(n) &= \phi_0 n^{\log_b a} + \sum_{h = 1}^{\log_b n} \dfrac {n^{\log_b a}}{a^h} \Theta(a^h (h\log b)^k) \\
> &= \phi_0 n^{\log_b a} + \sum_{h = 1}^{\log_b n} \Theta(n^{\log_b a} (h\log b)^k) \\
> &= \phi_0 n^{\log_b a} + \Theta(n^{\log_b a} (\log b)^k)\underbrace{\sum_{h = 1}^{\log_b n} h^k}_{\Theta((\log_b n)^{k + 1})} \\
> &= \Theta(n^{\log_b a} \times (\log n)^{k+1}).
> \end{align*}
> $$

- Otherwise, if $f(n) = \Omega(n^{\log_b a + \epsilon})$ for some $\epsilon > 0,$ then the work at the root node dominates (inner roots term is asymptotically significant), meaning $T(n) = \Omega(n^{\log_b a + \epsilon}).$

> Inner terms are $$
> \dfrac{n^{\log_b a} \Omega(a^{h} b^{h\epsilon})}{a^h} = \Omega{(n^{\log_b a} b^{h\epsilon})},
> $$
> which is montonically increasing in $h$ and thus maximal at $h = \log_b n$, yielding
> $$
> T(n) = \Omega(n^{\log_b a + \epsilon}).
> $$

- Finally, if $f(n) = \mathcal O(n^{\log_b a - \epsilon})$ for some $\epsilon > 0,$ the work at the leaves dominates. The inner terms resolve to
$$
T_h = \dfrac{n^{\log_b a}}{a^h} f(b^h) = \mathcal O(n^{\log_b a }b^{-h\epsilon}),
$$
making the leaves term dominate, yielding $T(n) = \Theta(n^{\log_b a}).$

##### regularity conditions for $f(n) = \Omega(\ldots)$
Notice that Case 2 is the only one that can't assert an equality asymptotic bound. We can resolve this by assuming regularity, i.e for sufficiently large $n,$ there is some $c$ such that $$
af(n/b) \leq cf(n).
$$

Trivially, $T(n) = \Omega(f(n)),$ so we must just show that $T(n) = \mathcal O(f(n)).$

From regularity, we get $f(n/b) \leq \frac{c}{a}f(n),$ meaning 
$$
f(n/b^k) \leq \left(\frac{c}{a}\right)^k f(n).
$$
Plugging this in, we get
$$
T_h = \dfrac{n^{\log_b a}}{a^h} f\left(\dfrac{n}{b^{\log_b n - h}}\right) \leq \underbrace{\dfrac{n^{\log_b a}}{a^{\log_b n}}}_{=1} \cdot c^{\log_b n - h} f(n).
$$
Hence, the sum satisfies
$$
\begin{align*}
\sum_{h = 1}^{\log_b n} T_h &\leq f(n) \sum_{h = 1} ^{\log_b n} c^{\log_b n - h} \\
&= f(n) \sum_{h = 0} ^{\log_b n - 1} c^{h} \\
&\leq f(n) \cdot \dfrac{1}{ 1 - c} = O(f(n)),
\end{align*}
$$
meaning $T(n) = O(f(n)),$ since the leaf term is asymptotically dominated. Hence, we can conclude $T(n) = \Theta(f(n)).$

## divide and conquer
### examples
#### multiplication of $n$-bit numbers faster than $\mathcal O(n^2)$ (Karatsuba)
**Divide and conquer:** Our problem setup involves the mulitplication of two bit strings (base 2) of length $n.$ Naively, we can split bit strings $[A_1 A_2] \times [B_1 B_2]$ into $$
A_1 B_1 2^{n} + (A_1 B_2 + A_2 B_1) 2^{n/2} + A_2 B_2.
$$
Naively, this produces a recurrence:
$$
T(n) = 4T(n/2) + \mathcal O(n),
$$
which via the master theorem is $\mathcal O(n^2),$ which is not an improvement. However, notice that we can express 
$$
A_1 B_2 + A_2 B_1 = (A_1 + B_1)(A_2 + B_2) - A_1 B_1 - A_2 B_2,
$$
which now requires only 3 recurrences per step, yielding an asymptotic complexity of $\mathcal O(n^{\log_2 3}).$ This is called the Karatsuba algorithm.

#### find $k$-th smallest in two sorted arrays
Suppose we have two arrays $A[1 \ldots m]$ and $B[1 \ldots n],$ sorted in increasing order. WLOG, let $m < n.$ Consider the case where the $k$-th smallest element $k_0$ is in $A.$ Then, for some index $r < k,$ $A[r] = k_0.$ This means there are $k - r$ elements in $B$ that are smaller than $k_0,$ with it being sorted in increasing order. We can search on this index $r$ in a divide-and-conquer style. 

We want to achieve this in $\mathcal O(\log (m + n))$ time, meaning using divide and conquer we can afford to recurse once on half the input size, and perform $\mathcal O(1)$ work.

Notice that finding the median is equivalent to finding the $(m + n)/2$-th element. When the $r$-th element in $A$ is the median, the first $(m + n) / 2 - r$ of elements in $B$ must be less than $A[r],$ and the converse for the remaining elements. Vice-versa if the $r$-th element in $B$ is the median.

To divide and conquer, let us try and find the $k$-th largest element. Consider a balanced guess that the median is one of $A[k/2],$ $B[k/2].$ We want to be able to eliminate some elements from our search space, and recurse to a smaller $k.$ Can we guarantee elements in $A$ or $B$ aren't the $k$-th largest?

If $A[k/2] < B[k/2],$ then $A[k/2]$ cannot be the $k$-th largest element, since there are at most $k - 1$ elements smaller than $A[k/2].$ Hence, we can exclude the entire length $k/2$ prefix of $A,$ and find the $k/2$-th largest element in $A[k/2 + 1 \ldots m], B[1 \ldots n].$

#### find all elements that occur more than $n/3$ times
Given $A[1 \ldots n],$ find all elements that occur more than $n/3$ times.

We proceed by noticing that an element that occurs $> n/3$ times in $A[1 \ldots n]$ must occur $> n / 6$ times in $A[1 \ldots n/2]$ or $A[n/2 + 1 \ldots n].$ Hence, we can find all such elements in the left and right subarray, and then check each manually in $\mathcal O(1)$ time, since at worst case we have $4$ elements to check.

#### sorting pancakes
Suppose you are given a stack of n pancakes of different sizes. You want to sort the pancakes so that smaller pancakes are on top of larger pancakes. The only operation you can perform is a flip—insert a spatula under the top $k$ pancakes, for some integer $k$ between 1 and n, and flip them all over.

- Describe an algorithm to sort an arbitrary stack of n pancakes using $\mathcal O(n)$ flips

To achieve this sorting, we sort recursively. Given $A[1 \ldots n],$ we first place the minimum element at $A[1],$ and then sort $A[2 \ldots n].$

To place the minimum element at $A[1],$ let $A[k]$ be the initial minimum element. Then, flip $k \ldots n,$ and then flip the entire array, making $A[1]$ minimal. Then recurse.

- For every positive integer $n$, describe a stack of n pancakes that requires $\Omega(n)$ flips to sort

We want each recursive step to require flipping twice. Place the smallest pancake at index $1,$ the largest at index $2,$ the second smallest at $3,$ etcetera.

#### StoogeSort
Prove that the following algorithm works:
```
StoogeSort(A[0 .. n − 1]):
    if n = 2 and A[0] > A[1]:
        swap(A[0], A[1])
    else if n > 2:
        m = 2n / 3 
        StoogeSort(A[0 .. m − 1])
        StoogeSort(A[n − m .. n − 1])
        StoogeSort(A[0 .. m − 1])
```
We prove the algorithm functions inductively. For $n = 1, 2,$ the algorithm is trivially correct. Then, assume the algorithm is correct for all input sizes $1 \leq k \leq n - 1,$ for some integer $n > 2.$

After the first sort, positions $A[n/3 + 1 \ldots 2n/3]$ are in sorted order, and guaranteed to be larger than the $n / 3$-rd entry in the sorted array. Similarly, positions $A[1 \ldots n/3]$ are guaranteed to be less than the $2n / 3$-rd entry in the sorted array. 

In other words, if $A[j]$ lies after index $2n/3$ in the sorted array, it will be after index $n/3$ during this step. Then, the next sort will place all such $A[j]$ in the upper third of the array, placing them in the correct position. Hence, $A[1 \ldots 2n/3]$ will consist of a permutation of the sorted array $A'[1 \ldots 2n/3],$ and by our inductive hypothesis sorting these elements will succesfully sort the array.

Recurrence: $T(n) = 3T(2n/3) + \mathcal O(1),$ i.e $c_\text{crit} = \log_{3/2}(3),$ meaning $T(n) = n^{\log_{3/2}{3}} = n^{1 + \log_{3/2} 2}.$
